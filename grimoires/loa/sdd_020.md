## 1. Architecture Overview

Cycle 020 hardens two backend runtime surfaces:

1. Scenario Pack checkpoint execution becomes truly schema-driven for `RUNNABLE` templates.
2. Paradox risk becomes a live orchestrated policy signal instead of a mostly read-time fallback.

```text
┌──────────────────────────────────────────────────────────────────────────┐
│                           CYCLE 020 ADDITIONS                           │
│                                                                          │
│  ┌────────────────────┐   ┌──────────────────────┐  ┌──────────────────┐ │
│  │ Checkpoint         │   │ Scenario Seed        │  │ Paradox Risk     │ │
│  │ Evaluator v2       │   │ Manager              │  │ Orchestrator     │ │
│  │                    │   │                      │  │                  │ │
│  │ trigger_condition  │   │ mode-aware seed      │  │ mutation hooks   │ │
│  │ branch_rule        │   │ allocation           │  │ persist + emit   │ │
│  │ reward_mapping     │   │ replay parity        │  │ material delta   │ │
│  │ spawn_rule         │   │ deterministic RNG    │  │ inquiry-aware    │ │
│  └─────────┬──────────┘   └──────────┬───────────┘  └────────┬─────────┘ │
│            │                         │                        │           │
│  ┌─────────▼─────────────────────────▼────────────────────────▼─────────┐ │
│  │                         Existing Runtime Surfaces                     │ │
│  │  ScenarioPack routes | TheatreSpawner | Replay/Tree | Theatre API   │ │
│  │  Investigation routes | Paradox task | WebSocket manager            │ │
│  └──────────────────────────────────────────────────────────────────────┘ │
└──────────────────────────────────────────────────────────────────────────┘
```

### 1.1 Data Flow

**Scenario run resolution**

```text
POST /scenario-packs/{id}/run
  -> ScenarioPackLifecycle creates ScenarioRun
    -> ScenarioSeedManager assigns environment seed(s)
      -> CheckpointEvaluator v2 loads checkpoint graph
        -> ScenarioRunStateBuilder builds state vector for checkpoint N
          -> evaluator primitive validates trigger_condition_json
          -> evaluator primitive evaluates branch_rule_json
          -> reward computed from reward_mapping_json
          -> theatre spawn evaluated from theatre_spawn_rule_json
          -> RunCheckpointResult persisted
        -> tree/replay endpoints read recorded results, not reconstructed guesses
```

**Paradox risk orchestration**

```text
Mutation path occurs
  -> ParadoxRiskOrchestrator.recompute_if_needed(...)
    -> evaluate inquiry-class-aware risk
    -> compare with persisted risk snapshot
    -> persist updated level/factors/timestamp
    -> emit PARADOX_RISK_CHANGED only if material delta
  -> Theatre detail read remains fallback if snapshot missing/stale
```

## 2. Sprint 0 — Runtime Contract Tightening

### 2.1 Dependency Health Gate

Before runtime changes begin, Cycle 020 must verify upstream dependency health against current code:

- Cycle 017:
  - certificate routing fields present and stable
  - coherence gate lifecycle stable
  - websocket policy events not regressed
- Cycle 018:
  - scenario pack schema tables present
  - `RUNNABLE` vs `CATALOG_ONLY` template split intact
  - replay/tree/derived-theatre endpoints present and functioning
- Cycle 019:
  - investigation persistence path live
  - paradox-risk theatre fields present
  - deployment/investigation regressions green

This is not a historical re-audit of archived docs. It is a live implementation gate to ensure 020 upgrades current code, not superseded assumptions.

### 2.2 Evaluator Primitive Contract

Freeze the v1 primitive set and their configuration envelopes:

```python
EVALUATOR_TYPES = {
    "BINARY_RISK_GATE",
    "RESOURCE_DEPLETION",
    "DETECTION_EVENT",
    "TIMING_BREACH",
    "MISSION_COMPLETION",
}
```

Each primitive must define:

- accepted `trigger_condition_json` shape
- accepted `branch_rule_json` shape
- required checkpoint state inputs
- whether stochastic sampling is permitted
- whether spawn evaluation is meaningful

### 2.3 Materiality Rule For Paradox Risk

`PARADOX_RISK_CHANGED` should emit only when one of these occurs:

- risk level changes (`LOW` → `WATCH`, etc.)
- a configured material factor crosses a threshold band
- `active_paradox` flips

Non-material recomputes update persistence if needed but do not emit websocket noise.

## 3. Sprint 1 — Schema-Driven Checkpoint Evaluation

### 3.1 Replace Hash-Only Selection

**Current posture:** `checkpoint_evaluator.py` hashes `(checkpoint_id, agent_action, seed, evaluator_type)` to pick an index.

**New posture:** selection must evaluate stored checkpoint configuration.

Proposed structure:

```python
class CheckpointEvaluationContext(BaseModel):
    checkpoint_id: str
    evaluator_type: str
    environment_seed: int
    agent_action: str
    checkpoint_state: dict
    trigger_condition: dict
    branch_rules: list[dict]
    reward_mapping: dict
    theatre_spawn_rule: dict | None


class EvaluatorOutcome(BaseModel):
    selected_branch_id: str
    reward: float
    state_vector: dict
    trigger_satisfied: bool
    spawn_allowed: bool
    debug_factors: dict
```

### 3.2 Branch Rule Model

`CheckpointBranch.branch_rule_json` becomes executable config rather than passive metadata.

Minimum common structure:

```json
{
  "rule_type": "threshold | categorical | stochastic_band | terminal",
  "inputs": ["agent_action", "risk_score", "resource_level"],
  "operator": "eq | ne | gte | lte | between | in",
  "value": "...",
  "priority": 10
}
```

Primitive-specific validators constrain the allowed keys beyond this shared envelope.

### 3.3 Trigger Condition Model

`ScenarioCheckpoint.trigger_condition_json` gates whether a checkpoint is ready to resolve.

Example:

```json
{
  "kind": "state_threshold",
  "field": "elapsed_steps",
  "operator": "gte",
  "value": 3
}
```

Or:

```json
{
  "kind": "event_seen",
  "field": "courier_intercepted",
  "value": true
}
```

If a runnable checkpoint lacks a valid trigger contract, run launch must fail fast rather than silently falling back.

### 3.4 Reward Computation

Reward precedence:

1. branch-level `reward_mapping_json`
2. checkpoint-level `reward_mapping_json`
3. default evaluator primitive reward

Reward output is then scaled by the template objective vector.

### 3.5 Failure Handling

Malformed runnable checkpoint graphs should not degrade silently.

Add explicit failure states:

- `INVALID_TRIGGER_CONFIG`
- `INVALID_BRANCH_CONFIG`
- `NO_MATCHING_BRANCH`
- `MISSING_STATE_INPUT`
- `INVALID_SPAWN_RULE`

These map to run failure records and API-visible error responses.

## 4. Sprint 2 — Environment RNG + Mode Semantics

### 4.1 ScenarioSeedManager

**New file:** `backend/services/scenario_seed_manager.py`

Responsibilities:

- allocate seeds for fresh runs
- allocate canonical seed sets for calibration/evaluation
- preserve replay seeds without mutation
- expose deterministic RNG instances for evaluator primitives

Suggested interface:

```python
class ScenarioSeedManager:
    def allocate_seed(self, run_mode: str, pack_id: str, user_id: str) -> int: ...
    def canonical_seed_set(self, template_id: str, run_mode: str) -> list[int]: ...
    def rng(self, seed: int, namespace: str) -> random.Random: ...
```

### 4.2 Determinism Boundaries

Deterministic replay requires separation of:

- agent action stream
- environment randomness
- persisted branch outcomes

Replay must never re-roll randomness. It reads recorded outcomes and state vectors.

### 4.3 State Builder

**New file:** `backend/services/scenario_run_state_builder.py`

Build a normalized checkpoint state input from run + prior results:

```python
{
  "elapsed_steps": 4,
  "prior_reward_total": 1.75,
  "branch_history": [...],
  "resource_level": 0.42,
  "hidden_flags": {...},
  "event_log": [...],
}
```

This keeps primitive evaluators deterministic and makes test fixtures stable.

## 5. Sprint 3 — Derived Theatre Rules + Run Integrity

### 5.1 Spawn Rule Model

Replace coarse `can_spawn_theatre` semantics with actual `theatre_spawn_rule_json` evaluation.

Shared rule envelope:

```json
{
  "enabled": true,
  "requires_outcome_type": "success",
  "min_reward": 0.5,
  "allowed_run_modes": ["TRAINING", "EVALUATION"],
  "template_override": null
}
```

`can_spawn_theatre` may remain as a legacy coarse flag, but the runtime should require spawn-rule pass for actual spawning.

### 5.2 Provenance

Spawned theatres must remain uniquely attributable:

- `construct_id = scenario_{pack_id}_run_{run_id}_cp_{checkpoint_id}`
- `spawned_from_checkpoint_id` retained
- query paths always scope through `RunCheckpointResult.run_id -> ScenarioRun.pack_id`

### 5.3 Audit Integrity

Theatre spawn should persist enough context to explain the origin:

- source pack id
- source run id
- source checkpoint id
- selected branch id
- reward snapshot
- environment seed

## 6. Sprint 4 — Paradox Risk Orchestration

### 6.1 Orchestrator Service

**New file:** `backend/services/paradox_risk_orchestrator.py`

Suggested API:

```python
class ParadoxRiskOrchestrator:
    async def recompute_for_theatre(
        self,
        session: AsyncSession,
        theatre_id: str,
        reason: str,
        emit_ws: bool = True,
    ) -> ParadoxRiskResult: ...
```

The orchestrator:

1. loads current theatre context
2. evaluates risk via `ParadoxRiskEvaluator`
3. compares old/new state
4. persists the new snapshot
5. emits event only if material delta

### 6.2 Trigger Points

Minimum trigger set:

- paradox task updates timeline stability / active paradox
- material counter-signal ingestion
- evidence freshness crossing threshold bands
- theatre detail read only if snapshot missing or stale

Future mutation hooks can be added, but these must exist in 020.

### 6.3 Persistence Model

Existing theatre fields remain:

- `paradox_risk_level`
- `paradox_risk_factors_json`
- `paradox_risk_updated_at`

No new table is strictly required unless audit history becomes necessary later.

### 6.4 Material Delta Comparison

Suggested comparison contract:

```python
class MaterialRiskDelta(BaseModel):
    level_changed: bool
    active_paradox_changed: bool
    factor_band_changes: list[str]
    should_emit: bool
```

Factor bands keep websocket emission stable even when raw float values wobble insignificantly.

### 7.1 Events

Add/confirm support for:

| Event | Meaning |
|------|---------|
| `CHECKPOINT_RESOLVED` | Rule-evaluated checkpoint completed |
| `THEATRE_SPAWNED` | Spawn rule produced a theatre |
| `PARADOX_RISK_CHANGED` | Material risk delta detected |

### 7.2 Payload Contracts

```json
{
  "event_type": "CHECKPOINT_RESOLVED",
  "pack_id": "...",
  "run_id": "...",
  "checkpoint_id": "...",

```

```json
{
  "event_type": "PARADOX_RISK_CHANGED",
  "theatre_id": "...",
  "old_level": "WATCH",
  "new_level": "HIGH",
  "factors": {...},
  "reason": "material_counter_signal"
}
```

### 7.3 Integration Tests

Required end-to-end paths:

1. Scenario Pack:
   - runnable template
   - create pack
   - commit
   - run with fixed seed
   - checkpoint graph resolves from schema
   - derived theatre spawns only when spawn rule passes
   - replay reproduces exact path

2. Paradox risk:
   - mutation triggers recompute
   - persisted fields update
   - material change emits exactly one WS event
   - non-material recompute emits none

## 8. API Changes

### 8.1 Scenario Pack Endpoints

No route reshaping required. Existing endpoints should gain stricter runtime semantics:

- `POST /api/v1/scenario-packs/{id}/run`
  - validate executable checkpoint config
  - persist seed strategy
  - fail cleanly for invalid runnable graphs
- `GET /api/v1/scenario-packs/{id}/runs/{run_id}/tree`
  - reflect true evaluator outcomes
- `GET /api/v1/scenario-packs/{id}/runs/{run_id}/replay`
  - use recorded results and seed context

### 8.2 Theatre Endpoints

- `GET /api/v1/theatres/{id}`
  - return persisted paradox risk
  - fallback recompute only if missing/stale

List routes may later include richer risk freshness metadata, but Cycle 020 should avoid breaking stable theatre response contracts.
