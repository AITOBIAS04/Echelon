## 1. Problem Statement

Two backend surfaces are still not at release-grade fidelity.

### 1.1 Scenario Packs Runtime Is Persisted But Not Truthful Enough

Cycle 018 shipped the Scenario Packs Engine, but the runtime posture remains partially staged:

- checkpoints are stored with declarative schema fields
- templates are split into `RUNNABLE` and `CATALOG_ONLY`
- runs, replay, derived theatres, and telemetry exist

But the evaluator still does not honour the stored checkpoint contract end to end:

- branch selection is still hash-based rather than rule-evaluated
- `trigger_condition_json` is not the real execution driver
- `branch_rule_json` is not the real branch selector
- `theatre_spawn_rule_json` is not the real theatre-spawn gate

That was acceptable while Scenario Packs were emerging. It is not acceptable if `RUNNABLE` templates are now treated as real training, evaluation, calibration, and replay environments.

### 1.2 Paradox Risk Exists But Is Not Yet A Live Operational Signal

Cycle 019 made paradox risk visible on theatre detail responses, but it is still only partially operational:

- it can compute on read when missing/stale
- it persists to theatre state

But it is not yet driven from all relevant mutation paths, and it is not yet a clean evented policy surface:

- no complete orchestration across paradox task, investigations, and material counter-signals
- `PARADOX_RISK_CHANGED` is not yet guaranteed to fire only on material delta
- risk is not yet fully upgraded from cached field to live operational signal

### 1.3 Dependency Chain Needs A Health Gate

Cycle 020 sits on a long chain of shipped cycles. That is workable, but only if the upstream contracts it depends on are still clean:

- Cycle 017 policy surface must be stable and passing
- Cycle 018 scenario-pack schema/runtime must be internally coherent enough to upgrade
- Cycle 019 paradox-risk fields and investigation state must be stable enough to orchestrate

The repo history suggests some older context drift exists in archived materials. Cycle 020 should explicitly run a dependency-health check in Sprint 0 so execution is grounded in current code, not only in accumulated planning documents.

## 2. Product Contracts

### 2.1 Scenario Packs Are Real Runtime Products

For `RUNNABLE` templates, the stored checkpoint graph is the source of truth. The backend must behave accordingly.

That means:

- no bespoke Python per scenario pack
- no pretending that hash-only branching is “close enough”
- no hidden runtime semantics that disagree with the stored checkpoint contract

### 2.2 Checkpoint Evaluation Contract

Every runnable checkpoint must be executable from stored configuration:

- `trigger_condition_json`
- `decision_window_sec`
- `evaluator_type`
- `branch_rule_json`
- `reward_mapping_json`
- optional `theatre_spawn_rule_json`

Branch resolution must be deterministic given:

- agent action
- checkpoint state
- environment seed
- evaluator config

### 2.3 Environment Randomness Contract

Agents contribute decisions, strategies, and policies. They do **not** create randomness.

Randomness comes from the environment via explicit seeded RNG:

- event rolls
- hidden state variation
- saboteur deck draws
- bounded noise / uncertainty sampling

Mode semantics:

- `TRAINING` = stochastic, varying seeds
- `EVALUATION` = controlled stochasticity from a fixed seed set
- `CALIBRATION` = canonical seed set for comparability
- `REPLAY` = exact recorded path, no fresh randomness

### 2.4 Paradox Risk Contract

Paradox risk is a live policy signal.

It must:

- recalculate from real theatre/investigation/paradox mutation paths
- persist latest assessed state for efficient reads
- emit `PARADOX_RISK_CHANGED` only on material delta
- remain inquiry-class-aware

Theatre language remains bounded and credible:

- `LOW`
- `WATCH`
- `HIGH`
- Evidence weak
- Counter-signals rising
- Logic gap widening
- Stale investigation
- Paradox active

## 7. API Changes

### Scenario Packs

- `POST /api/v1/scenario-packs` remains restricted to `RUNNABLE` templates
- `POST /api/v1/scenario-packs/{id}/run` must fail when a runnable template has invalid/non-executable checkpoint config
- `GET /api/v1/scenario-packs/{id}/runs/{run_id}/tree` must reflect rule-evaluated branches
- `GET /api/v1/scenario-packs/{id}/runs/{run_id}/replay` must reproduce exact recorded path and environment outcomes

### Theatre / Paradox Risk

- `GET /api/v1/theatres/{id}` continues to return paradox risk, now primarily from orchestrated persisted state
- read-time recompute remains fallback only
- optional freshness/debug metadata may be additive if helpful, but no breaking contract changes
